# Заряд устройств: как добавить своё

Островок показывает заряд беспроводных мышей, клавиатур, гарнитур и геймпадов: `bat ` в поиске,
пик, когда заряд садится, и напоминание в капсуле, когда почти сел. Откуда он его берёт:

| Источник | Что покрывает |
|---|---|
| **Logitech HID++** | мыши, клавиатуры и гарнитуры Logitech: через приёмник (Unifying, Lightspeed, Bolt) и напрямую. Встроено в код. |
| **Bluetooth** | устройства, чей заряд уже знает Windows (видно в «Параметрах → Bluetooth»). Встроено. |
| **Рецепты** | всё остальное. Рецепт описывает протокол устройства данными, без кода, — их может написать любой. |

Рецепты лежат в [`devices/devices.json`](../devices/devices.json). Островок берёт эту базу из
репозитория раз в сутки, поэтому новое устройство появляется у всех без выпуска новой версии.

## Как это устроено

У беспроводных устройств заряд почти всегда можно спросить у приёмника: отправить короткий
пакет в его вендорскую HID-коллекцию и прочитать ответ. Каждый производитель делает это по-своему,
но схема одна и та же, и рецепт — ровно она:

```json
{
  "id": "ajazz-aj159-apex",
  "name": "Ajazz AJ159 APEX",
  "kind": "mouse",
  "connection": "dongle",
  "match": { "vid": "3151", "pid": "5007", "page": "FFFF", "usage": "0002" },
  "steps": [
    { "setFeature": "00 F7" },
    { "wait": 40 },
    { "getFeature": "05", "require": { "1": "00", "2": "00" }, "battery": { "at": 3, "valid": [1, 100] } }
  ],
  "source": "https://github.com/Aiacos/ajazz-control-center"
}
```

## 1. Найдите протокол

Сначала поищите готовый — скорее всего, его уже разобрали:

- [HeadsetControl](https://github.com/Sapd/HeadsetControl) — гарнитуры SteelSeries, Corsair, HyperX, Logitech, Audeze и другие;
- [rivalcfg](https://github.com/flozz/rivalcfg) — мыши SteelSeries;
- [OpenRGB](https://gitlab.com/CalcProgrammer1/OpenRGB), [Solaar](https://github.com/pwr-Solaar/Solaar),
  а также поиск на GitHub по `VID:PID` вашего приёмника и слову `battery`.

Эти проекты написаны на hidapi, и рецепт повторяет его поведение, поэтому байты переносятся как есть:
`hid_write(dev, {0x06, 0x18})` — это `{ "write": "06 18" }`, `hid_read` — `{ "read": {} }`,
индекс в ответе тот же.

Если готового нет — подсмотрите у фирменной программы: [Wireshark](https://www.wireshark.org/) с
USBPcap, фильтр по адресу приёмника, и ищите пакет, после которого программа обновляет процент
заряда. Удобно разрядить устройство на несколько процентов и сравнить ответы.

## 2. Посмотрите на устройство глазами островка

*Настройки → Интеграции → Устройства → **Отчёт***. Островок опросит всё подключённое и откроет файл:

- все HID-коллекции: `VID:PID`, номер интерфейса (`MI`), страница и usage, длины отчётов;
  вендорские (страница `FF00` и выше) помечены — разговаривать можно только с ними;
- для каждого рецепта — что отправлено и что пришло в ответ, байт за байтом.

## 3. Напишите рецепт и проверьте у себя

*Настройки → Интеграции → Устройства → **Свой devices.json*** откроет файл
`%APPDATA%\Islet\devices.json`. Островок подхватывает его сразу после сохранения; рецепт с тем же
`id`, что в общей базе, заменяет общий. Проверяйте в `bat ` и в отчёте.

### Поля

| Поле | Что это |
|---|---|
| `id` | уникальное имя: латиница, цифры, `-` `_` `.` |
| `name` | как показывать устройство |
| `kind` | `mouse`, `keyboard`, `headset`, `gamepad`, `other` |
| `connection` | `dongle` (по умолчанию), `wired`, `bluetooth` — подпись в выдаче |
| `match.vid`, `match.pid` | hex; `pid` может быть списком |
| `match.page`, `match.usage` | коллекция: только вендорская (`FF00`–`FFFF`) или `000C` |
| `match.interface` | номер интерфейса (`MI` из отчёта) — если страница у разных моделей разная |
| `steps` | шаги по порядку; без `steps` устройство просто отмечается подключённым |
| `source` | откуда протокол — ссылка на проект или ваш разбор |

### Шаги

| Шаг | Что делает |
|---|---|
| `{ "write": "06 18" }` | выходной отчёт; байт 0 — номер отчёта (`00`, если отчёты без номеров); дополняется нулями |
| `{ "read": { "timeout": 1000, "attempts": 8 } }` | ждёт входной отчёт; у отчёта без номера ведущий `00` отрезан, как в hidapi |
| `{ "setFeature": "00 F7" }` | feature-отчёт |
| `{ "getFeature": "05" }` | прочитать feature-отчёт с этим номером; номер остаётся в байте 0 |
| `{ "wait": 40 }` | пауза, до 500 мс |
| `{ "flush": true }` | выбросить накопившиеся входные отчёты — чтобы старый ответ не сошёл за новый |

К `write` можно добавить `"length": 20` (дополнить пакет до длины) и
`"checksum": { "from": 0, "to": 18, "at": 19 }` (сумма байтов по модулю 256).

К `read` и `getFeature` — разбор ответа. Байты указываются номером, значения — hex;
`"4A/7F"` значит «байт под маской 7F равен 4A», список — «любое из»:

| Поле | Что это |
|---|---|
| `match` | (только `read`) не тот отчёт — читать следующий |
| `require` | не совпало — заряд неизвестен |
| `offline` | совпало — устройство не на связи (гарнитура выключена, а база подключена) |
| `charging` | `{ "at": 4, "equals": ["01"] }` или `{ "at": 1, "mask": "80" }` — заряжается |
| `battery` | где заряд — см. ниже |

`battery`:

| Поле | Что это |
|---|---|
| `at` | номер байта |
| `mask` | маска, например `7F`, если в старшем бите флаг |
| `word` | `be` или `le` — два байта (напряжение в мВ) |
| `valid` | `[мин, макс]` — сырое значение вне диапазона означает «не знаю» (не 0 %!) |
| `range` | `[мин, макс]` — перевести в проценты линейно: уровни `[0, 4]`, `[0, 8]` |
| `curve` | `[[сырое, %], …]` — кривая, обычно напряжение → проценты |

### Ограничения

Рецепт шлёт байты прямо в устройство, поэтому островок строг:

- только вендорские коллекции (и `000C`), клавиатуру и мышь трогать нельзя;
- до 16 шагов, пакеты до 64 байт, паузы до 500 мс, чтение до 1,5 с, весь рецепт — до 3 секунд;
- не ответило — пауза до следующей попытки растёт до получаса.

**В рецепт идут только запросы состояния.** Никаких команд, которые что-то меняют в устройстве:
DPI, подсветка, режимы, прошивка. Если не уверены, что байт только спрашивает, — не отправляйте его.

## 4. Пришлите в общую базу

Pull request с изменением `devices/devices.json`:

- рецепт проверен на вашем устройстве — напишите модель и что показал островок;
- в `source` — откуда протокол;
- увеличьте `revision` в начале файла на 1.

Каждый рецепт смотрится вручную, прежде чем попасть в базу.
